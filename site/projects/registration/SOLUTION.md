# Reference reasoning: Build a registration form

The download and wrapped chapter example load the same maintained local behaviour. Disabled fieldset descendants cannot be used for the application task before successful setup. Once handlers are installed, the script enables them and suppresses form navigation with preventDefault(). The summary supplies a focused overview and links that explicitly focus each failed control. A polite status reports only that the browser checks passed. No confirmation of membership, delivery or server acceptance is justified. See assets/project-registration.js in the site source, or demo.js in the ZIP, for the complete validation and reset implementation.

## Explained exercise answer

A fragment names a destination within a resource; it does not cancel form submission. A GET form with named controls can place values in the URL and navigate even without an application backend. This reference therefore starts with disabled fields and enables them only after the local submit/error/reset handlers are installed. If the script is blocked, the instructions remain and the fields stay disabled. Reset clears the controls, the summary list, inline messages, aria-invalid attributes and the custom validity message on the name. The result reports reset, not application acceptance. Test reset again after a valid local check, since stale success text can otherwise survive.

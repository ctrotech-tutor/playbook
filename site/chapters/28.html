Chapter 28

Images with a purpose

The alternative depends on why the image is there.

3 MIN READ + PRACTICESOURCE-LINKED PRACTICEOCTOBER 2026
By the end of this chapter
  • Choose alternatives from purpose and context
  • Use dimensions and loading hints deliberately
  • Distinguish resource success from the image complete flag

An img embeds an image. Its src identifies a resource; alt supplies a text alternative according to the image's purpose. Useful alternative text requires the actual image and its context. A filename or a generic image description is not enough evidence.

For a purely decorative image, alt="" can keep it out of the ordinary text alternative. Do not omit alt as a casual way to say decorative. A functional image in a link needs an alternative that communicates the link's purpose if no other accessible wording provides it.

Reserve the space

Provide width and height when you know the intended image dimensions or ratio. CSS can still size the rendered image responsively. Reserving an aspect ratio helps avoid layout movement as the resource loads.

Use loading="lazy" for suitable off-screen images, not automatically for the likely largest above-the-fold image. decoding and fetchpriority are hints with defined behavior and implementation limits. Measure before claiming a performance improvement. A broken src and a valid alt are different tests: an alternative does not make a missing image resource successful.

Inspect the resource as well as the attribute

The running example now uses the supplied teaching schematic. Compare the reading room, reception and lift with the alternative before adopting its wording. A logo used as the only content of a home link needs to name that destination; a decorative divider can have an empty alternative. Those decisions come from purpose, not file format.

complete can be true for a broken image as well as a successfully fetched one. Check the image's actual state and natural dimensions rather than declaring success from that flag alone. decode() returns a promise for decoding; it can reject with an EncodingError when the image cannot be decoded. Handling that rejection is different from supplying useful alternative text.

decoding permits sync, async and auto; missing or invalid values select Auto. fetchpriority permits high, low and auto, with Auto as its missing and invalid default. These preferences do not guarantee a loading order or a performance gain. Lazy loading is a separate policy and should fit the image's position and purpose.

crossorigin="anonymous" requests CORS-enabled fetching without cross-origin credentials. It does not make a server grant access. Drawing a cross-origin image into a canvas without the required CORS access can make the bitmap unavailable for pixel readback. Chapter 33 explains that security boundary.

The example

HTML / example 28
<img src="../assets/library-floor-plan.svg"
     alt="The reading room is left of reception; the lift is opposite."
     width="640" height="360" decoding="async">
<p>Fictional teaching schematic, not directions to real premises.</p>

The supplied original schematic has a 640 by 360 view. Its alternative gives the two spatial relationships relevant here. The decoding preference is a hint, not a measured performance result. The same image could need different wording in a different context.

A mistake to watch forWriting alt="image" or alt="photo" while leaving out the information the image contributes.

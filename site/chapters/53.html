Chapter 53

Attributes and properties

Source text, defaults and current state can diverge.

3 MIN READ + PRACTICESOURCE-LINKED PRACTICEOCTOBER 2026
By the end of this chapter
  • Distinguish raw attributes and current state
  • Read the correct layer when debugging controls
  • Trace dirty/default/reset behavior and special reflection cases

getAttribute reads an attribute's text or returns null when absent. A corresponding DOM property can expose a parsed, normalized or stateful value. Do not assume they always remain equal.

For a text input, the value attribute is associated with its default value, while the value property describes the current value under the control's rules. User edits can change the current value without rewriting the source attribute. checked and defaultChecked have a related distinction for appropriate controls.

Read the right layer

Boolean reflection commonly maps property true to attribute presence and false to absence. URL properties can return resolved absolute URLs while the attribute contains a relative string. Numeric reflection has its own rules, defaults and limits.

When debugging, ask whether the question concerns the original source, the current attribute, or the current control state. Reset behavior, script assignment and user interaction can affect different layers. Avoid a generic helper that treats every attribute and property as interchangeable strings.

Default state follows its own update rules

Before a text input has a dirty current value, changing its value attribute can update the current value as well. After an edit or a value-property assignment, that synchronization changes; defaultValue can change without replacing the current text. A form reset restores the relevant default under its rules. Inspect the actual state instead of assuming every setAttribute call has the same result.

Nonce is a deliberate special case: the connected element's getAttribute("nonce") can be empty while its nonce property retains the internal nonce. Source text, current content attribute and internal state are not three interchangeable strings.

Collections can have different result shapes

form.elements includes listed controls associated with that form, including eligible external controls, but has the historical image-button exception. namedItem can return a single element, a RadioNodeList when several match, or null. A RadioNodeList value concerns its checked radio, not a generic serialization of every checkbox. Use the form entry-list APIs for repeated submitted values.

select.options is a live options collection with its own indexed/add/remove behavior. selectedOptions has a separate current-selection purpose. Do not freeze a live collection assumption into a mutation loop without checking which nodes remain.

document.all is a legacy compatibility object with unusual falsiness and typeof behavior. It is not a recommended feature-detection API. A member inventory must retain that legacy behavior honestly, without encouraging it in new application code.

The example

HTML + JavaScript / example 53
<label for="nickname">Reading-group name</label>
<input id="nickname" name="nickname" value="Guest">
<script>
  const field = document.getElementById("nickname");
  field.value = "Ada";
  console.log(field.value);                 // Ada
  console.log(field.getAttribute("value")); // Guest
</script>

The script changes the current input value. The attribute retains Guest in this example. This is a specific input-state behavior, not a universal rule for every property named value.

A mistake to watch forUsing getAttribute("value") to read a text field after the user has edited it.

Your turn

Check your understanding

Which should an ordinary script read for the current text input value after editing? Can setting the value attribute affect a pristine input differently from one already edited?

Read the explained answer

Read the input's value property. If you need the default value or the raw attribute, ask for that specifically instead of assuming it equals the current state. Yes. The dirty-value rules matter. Reset uses the relevant default, and nonce hiding is another reason not to assume getAttribute always reproduces the original source spelling.

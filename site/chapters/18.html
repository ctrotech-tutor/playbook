Chapter 18

Lists with a reason

Order and relationships determine the markup.

3 MIN READ + PRACTICESOURCE-LINKED PRACTICEOCTOBER 2026
By the end of this chapter
  • Distinguish ordered, unordered and description lists
  • Nest a list under the item it expands
  • Explain what menu supplies and what it does not implement

Use ul for a group whose order is not significant, and ol when sequence or rank is part of the meaning. Each item is an li. A navigation menu is often a list of links, but not every group of adjacent items needs list markup.

A description list uses dl, dt and dd for name-value groups. A group can have multiple terms or multiple descriptions. It is not limited to dictionary definitions and does not require a table-like visual layout.

Keep nested lists inside an item

A sublist belongs inside the li it expands. A list placed beside an li is not that item's nested list. Markup should explain the relationship before CSS adds indentation.

For ordered lists, start and reversed can change the numbering behavior, and an li value can set an item's ordinal value in an ol. These are useful when the displayed order has meaning. Avoid using list markers as a substitute for actual text if readers need the text outside that presentation.

Commands and description groups

menu represents an unordered list of commands, a semantic alternative to ul for that purpose. <menu><li><button type="button">Copy</button></li><li><button type="button">Paste</button></li></menu> describes two command items; it does not implement either action. It is not the ARIA menu-widget pattern and does not automatically provide arrow-key navigation, a popup or a context menu.

In a dl, one or more dt names precede one or more dd values in each group. Keep several paragraphs belonging to one value in the same dd. A permitted alternative wraps each complete name-value group in a div, for example <dl><div><dt>Saturday</dt><dd>10:00 to 14:00</dd></div></dl>. Do not mix direct groups and div-wrapped groups as if the two content-model alternatives were interchangeable.

For a reversed ol without an explicit start, the initial ordinal is based on the number of its list-item children. A value on an li can change that item's ordinal and the sequence that follows. Check source order as well as marker styling; CSS counters are a separate presentation mechanism.

The example

<ol>
  <li>Choose a book.</li>
  <li>Check the lending period.
    <ul><li>Reference books have separate rules.</li></ul>
  </li>
  <li>Take the book to the desk.</li>
</ol>

Your turn

Check your understanding

Which structure fits opening hours grouped by day names: an ordered list of steps or a description list? Does menu implement a popup and its keyboard controls?

Read the explained answer

A description list is a reasonable choice for day names and their hours because the groups describe name-value relationships. A table may be better when readers need to compare a regular grid of days and multiple time ranges. An ordered list communicates that order matters; it does not inherently mean a procedure. Use it if the ordered sequence itself is the point, rather than merely to pair each day with its hours.

Chapter 50

Metadata readers encounter

A good title helps someone find the right tab again.

2 MIN READ + PRACTICESOURCE-LINKED PRACTICEOCTOBER 2026
By the end of this chapter
  • Write a specific document title
  • Describe metadata without search-result guarantees
  • Keep metadata consistent with visible content and base authoring

title identifies the document in browser UI and other contexts. Make it specific enough to distinguish this page from the rest of the site. A visible h1 and the document title have related but separate jobs.

meta can declare encoding or named metadata. A description is useful page-summary metadata, but its presence does not guarantee that a search engine will display it. Do not promise rankings from a tag.

Keep head deliberate

Use link for supported resource relationships such as stylesheets and icons. A favicon is not the same as a visible logo. style holds embedded CSS when permitted. base changes URL resolution and target defaults, so use it only when you understand the effects on every relative reference.

Metadata names and link types have defined or registered meanings. Do not invent a plausible name and assume a consumer understands it. Social sharing formats also need their own current documentation. Keep canonical URLs accurate, and avoid adding several conflicting declarations through independently configured tools.

One mechanism does not impersonate every response header

Choose the appropriate meta form: encoding, named metadata or a defined pragma. http-equiv is not an arbitrary way to set every HTTP response header. A meta-delivered CSP has important limitations, including directives that require response-header delivery; it is not identical to a header policy. Automatic refresh also has navigation and accessibility consequences.

A document has at most one base, with href, target or both. Put its href before other URL-bearing elements and its target before relevant hyperlinks. Browser handling that ignores later duplicate bases does not authorize duplicate authoring. An explicit link target can override the default target, while a fragment-only URL can still resolve against the changed base.

Style and stylesheet relationships need permitted contexts and real CSS resources. Named metadata, consumer-specific social formats and the document title have different contracts. Keep the body and annotations aligned before optimizing for a hypothetical search display.

The example

HTML / example 50
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="description" content="A teaching page with fictional opening hours and a contact-status notice.">
  <title>Visit and contact | Teaching library</title>
</head>
<body>
  <h1>Visit and contact</h1>
  <h2>Example hours</h2>
  <p>Tuesday to Saturday, 09:00 to 17:00. Fictional hours for teaching.</p>
  <h2>Contact status</h2>
  <p>Real contact details are not configured in this example.</p>
</body>
</html>

The description now matches the actual fictional hours and contact-status notice in the body. Neither the metadata nor the page advertises a real library service or promises a particular search snippet.

A mistake to watch forGiving every page the same title, or treating a meta description as a guaranteed search-result advertisement.
